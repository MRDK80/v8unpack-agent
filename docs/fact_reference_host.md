# Предложение ссылок на факты (opt-in reference host)

`examples.fact_reference_host.FactReferenceHost` — отдельный пример host,
не новый default прежнего клиента и не CLI. Host заранее выбирает полный
`TaskEvidence`, уникальный для запроса ASCII `scope_id` и отдельный разрешённый
output directory. Перед созданием проверяется актуальность снимка.

`observation()` возвращает `fact_selection_context/1`: scope и прежний
task evidence, дополненный короткими `ref` F1…Fn. Все исходные name/value
остаются недоверенными. `schema()` описывает только синтаксис предложения:
`{"scope_id":"…","fact_ids":["F1","F2"]}`. Схема не кодирует правильный
полный набор. `execute()` отдельно проверяет точные ключи, типы, scope,
отсутствие повторов и полноту набора. Неизвестные/чужие/пропущенные ссылки
не дополняются. Порядок предложения не меняет порядок отчёта из источника.

Модель не задаёт operation/module/output, новое evidence или текст отчёта.
Host материализует значения из своих фактов и передаёт предложение прежнему
независимому `ReportExecutor`: повторная проверка исходных байтов, семантики
и атомарная no-clobber запись остаются обязательными. Здесь нет нового
обходного writer. `native()` принимает ровно один read_source/select_facts
call; несколько вызовов отклоняются до dispatch. `strict_proposal()` принимает
ровно JSON object, запрещает дубликаты ключей/NaN/прозу; не извлекает команду
из Markdown и не переключается на другой протокол.

Scope — host корреляция, не секрет или полномочие. Host обязан не переиспользовать
его для разных запросов. Доступ к известному scope не позволяет подменить
операцию или произвольный файл. Это Python reference, не изоляция от исполнения
кода в процессе host. Условия эксклюзивного источника, отдельного output и
TOCTOU из [executor](action_validation.md) сохраняются.

Host уже знает полный статический ответ. Успешный выбор ссылок измеряет
соблюдение протокола моделью, а не её способность вычислить факты и не
универсальную устойчивость. Для такой задачи можно обойтись без LLM:
`make_report_proposal` и тот же validator. Строки готового отчёта всё ещё tainted.

Предварительный протокол [R11](research/fact_references_issue497_plan.md)
сравнивает прежний evidence native клиент с новыми native/JSON вариантами.
Ollama local поддерживает JSON schema через `format`
([официальное описание](https://docs.ollama.com/capabilities/structured-outputs),
[chat API](https://docs.ollama.com/api/chat)); синтаксические ограничения
не дают семантической проверки или полномочий. Фактические версия/профили,
ошибки и результаты фиксируются в отдельной серии до нового допуска.
Исторические NO-GO и default не меняются автоматически.

## Версии native адаптера

v1 сохранена неизменной и остановлена после 50 строк: реальный Ollama
добавляет `function.index`, который исходный строгий native parser отклонял.
Полный частичный ledger и исходники сохранены; это не завершённая серия.
`examples.fact_reference_host_v2` принимает только необязательный служебный
`index` точного типа int со значением 0 для одного вызова. Остальные ключи,
аргументы, проверка ссылок, prompts и schema те же. v2 — отдельная серия,
повтор известного development раскрыт. Ошибочный выбор моделью fact_id
вместо ref не исправлялся автоматически или изменением инструкции.
