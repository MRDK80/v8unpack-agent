# Динамический анализ в FormContext (#217)

`build_form_context(entry, root, include_dynamic_analysis=True)` включает
локальный detector/linker #214/#215. По умолчанию анализ выключен:
`FormContext.dynamic_analysis is None`, дополнительных чтений и проходов
анализатора нет; прежние metadata, фрагмент и post-run report сохраняются.
Прототип data flow #216 не подключается. В opt-in пути BSL читается с
сохранением исходных переводов строк: SHA и смещения операций относятся
к точному UTF-8 снимку. Default-off сохраняет прежнее чтение текста.

```python
from v8unpack_agent.form_context import build_form_context, to_llm_prompt_fragment

context = build_form_context(entry, root, include_dynamic_analysis=True)
fragment = to_llm_prompt_fragment(context, representation="framed")
```

`dynamic_forms_context` экспортирует `DynamicFormAnalysis`,
`DynamicAnalysisSummary` и `analyze_dynamic_form`. Последняя принимает
прочитанный BSL, относительный путь, пути метаданных и элементов формы.
Она читает ограниченные снимки, проверяет опись верхнего уровня через
`form_evidence`, тип формы и typed namespace существующего `elem_parser`.
Недоступный инвентарь не заменяется пустым полным списком. При изменении
снимка во время построения возвращается `incomplete`.

## Данные и статусы

Declared-дерево остаётся в `summary`; динамический слой его не переписывает.
`DynamicFormAnalysis.index` содержит отдельные raw, bound, кандидаты и связи.
`status` — `complete`, `incomplete`, `unsupported` или `unavailable`;
`reason` — стабильная причина отказа. При отказе `index=None`, а не пустой
полный индекс. `complete` означает завершённый анализ в закрытом scope,
а не полное покрытие BSL и не гарантированное runtime-дерево.

Идентичность ссылки, имя, значение и операция сохраняют независимые статусы.
Exact-ссылка на доказанное создание допустима при partial-имени.
Conditional — отдельный признак, совместимый с exact/partial/unresolved;
выражение guard известно по источнику, runtime-истинность остаётся unknown.
Ссылка действует только в сохранённом контексте ветви. `conditional`
считает наличие сохранённых guards; при `condition_context_complete=False`
отсутствие guard не доказывает безусловность операции.

`to_dict(include_expressions=False)` сохраняет полный индекс без текстов
выражений; `projection()` использует только bound-операции, условия и
кандидатов, без повторного raw-представления. В projection указаны
`runtime_state="not_reconstructed"` и `runtime_execution="unknown"`.
Это представления приватных исходных данных, а не обезличенные отчёты:
имена, литералы и относительные пути остаются данными выгрузки.

## Проекция и бюджеты

Секция `## DYNAMIC_FORM_OPERATIONS` имеет имя `dynamic_form_operations`
для аргумента `sections`. Она находится перед BSL и выводится только при
наличии анализа. В `framed` весь её JSON — недоверенный блок `kind=text`;
имена и значения не интерполируются в доверенную служебную строку.
Сохраняйте [контракт недоверенных данных](untrusted_content_contract.md).

Секция атомарна в обоих режимах: если символьный или токенный лимит
пересекает её, она опускается целиком. Операция не остаётся без статуса,
часть JSON не выдаётся за полный набор. Малый бюджет может полностью
исключить динамический анализ из фрагмента; канонический объект и метрики
при этом сохраняются. Default-off `legacy` и `framed` не меняются.
Счётчик токенов передаётся вызывающим; интеграция не запускает модели.

## Runner, CLI и отчёт

`RunOptions(include_dynamic_analysis=True)` включает тот же путь.
CLI предоставляет взаимоисключающие `--dynamic-analysis` и
`--no-dynamic-analysis`; default — выключено. Они доступны через
`--describe-cli`. Выбор `--representation framed` независим от включения
анализа и рекомендуется для передачи данных генерационной модели.

При включении post-run report получает `summary.dynamic_analysis`:
только неотрицательные целые счётчики, без BSL, имён и путей источников.
CLI JSON-envelope сохраняет прежнюю форму; новые агрегаты находятся в
полном отчёте по `--report-path`. Схема отчёта сохраняется; расширение
опционально и отсутствует при default-off.

Инварианты:

- `forms = complete + incomplete + unsupported + unavailable + failed`.
- `operations = exact + partial + unresolved` по bound-операциям.
- `conditional <= operations`; conditional не четвёртый resolution bucket.
- Каждая форма учитывается один раз; raw и bound не складываются.
- Число кандидатов отдельно: одна batch-операция может участвовать в
  нескольких кандидатах, поэтому их `operation_ids` не суммируются.

`failed` учитывает сбой построения контекста. Неполный, неподдержанный или
недоступный динамический анализ даёт форме `partial` с машинной причиной
`dynamic_analysis_*`, если нет более ранней причины деградации. Это
приводит к обычному degraded exit code. Отдельные unresolved-операции
в успешно построенном индексе сами по себе pipeline не деградируют.
Обычные формы не анализируются как управляемые: opt-in отмечает их
`unsupported`, не выдавая пустую полную опись.

При положительном символьном лимите formatter ограничивает BSL-префикс
по размеру кодированного блока, сохраняя прежний результат. Проверки
пользовательского токенного счётчика остаются в прежнем убывающем порядке:
его монотонность не предполагается. При token-only бюджете без символьного
предела такой произвольный счётчик может потребовать полного перебора.


[Итоговая матрица](dynamic_forms_coverage.md) и
[четыре конфигурации / два прогона](research/dynamic_forms_issue218.md)
отдельно показывают качество на gold и доступность анализа. Недоступные
namespaces не подменяются пустыми; дальнейшая работа — #562.
Лексическая/бюджетная причина отказа описывает предел анализатора,
а не обязательно невалидный BSL для платформы 1С.

## Создание элементов через общие модули (#566)

`v8unpack-agent-run EXPORT --report-path REPORT --common-form-creation`
включает отдельный проход. Общие модули индексируются один раз на прогон.
`--common-form-max-depth N` ограничивает число последовательных вызовов.
Без параметра ограничения глубины нет. Ноль отключает прохождение рёбер;
достигнутые отсечения видны в диагностике. Циклы завершаются благодаря
посещённым состояниям «процедура, позиция параметра, вид ссылки».

```python
from v8unpack_agent.common_form_creation import CommonFormIndex
from v8unpack_agent.form_context import build_form_context

modules = CommonFormIndex(root)
context = build_form_context(entry, root, common_form_index=modules)
evidence = context.common_form_creation
```

На уровне библиотеки `common_form_max_depth=None` означает обход без
лимита. Для каждой формы и позиции `Add`/`Insert` выводится один
кратчайший путь. Первый вызов имеет глубину 1. Переходы между модулями
указываются отдельно. При равной длине выбирается меньшее число переходов.
Передача отслеживается через явный аргумент формы или коллекции;
экспортные процедуры разрешаются по квалификатору общего модуля, а
помощники внутри модуля — по имени. Видимые переприсваивания отсекают
связь. Неизвестный эффект по ссылке и условная компиляция отмечаются
отдельно; достижимость при исполнении неизвестна. Динамические вызовы,
глобальные экспорты без квалификатора, алиасы и контейнеры значений
лежат вне этого прохода.

Результат проецируется в `DYNAMIC_FORM_OPERATIONS.common_form_creation`.
В `framed` это недоверенный текст; отчёт
`summary.common_form_creation` содержит только числовые агрегаты,
включая число форм с отсечениями и максимальную наблюдаемую глубину.
