# Проверка отчёта перед действием

`v8unpack_agent.action_validation` — opt-in library API для двух ограниченных
операций [evidence_context/1](evidence_context.md). Основание —
[ADR #480](research/agent_defense_adr_issue480.md). Пакет проверяет совпадение
отчёта с [синтаксическими фактами](bsl_facts.md), а полномочия пользователя
и разрешение записи задаёт host. API сам ничего не записывает.

Публичные имена: `ReportContract`, `ValidationResult`,
`create_report_contract`, `make_report_proposal`, `validate_report_action`.
Пример исполнителя: [examples/validated_report_executor.py](../examples/validated_report_executor.py).
Это пример для доверенного host, не зарегистрированный инструмент MCP.

## Контракт вне модели

```python
from pathlib import Path
from v8unpack_agent.action_validation import create_report_contract
from examples.validated_report_executor import ReportExecutor

# Host предварительно получил разрешение на конкретный модуль и отчёт.
# root/index/module_id и отдельный output_dir не берутся из исходника.
contract = create_report_contract(root, index, module_id)
executor = ReportExecutor(contract, root=root, output_dir=Path("reports"))

# Клиент собирает ВСЕ native calls из ОДНОГО ответа модели, декодирует JSON
# и передаёт [{"name": ..., "arguments": ...}] только этому wrapper.
result = executor.execute_calls(calls)
```

`create_report_contract(root, index, module_id, *, operation="exported_functions",
declaration_name=None)` фиксирует проверенные индексированные байты и снимок.
Неизвестный/неполный источник или неподдержанная операция не создают контракт.
Для `returned_string` host явно выбирает имя функции. Датакласс не является
секретным токеном: он принадлежит доверенному процессу, а не модели.
Подложный Python-объект от недоверенного плагина нельзя считать полномочиями.

Контракт содержит ModuleEntry, SourceSnapshot, operation и необязательное
имя функции. Адрес записи задаётся отдельно host исполнителю и отсутствует
в аргументах модели. `report.json` — единственное имя файла примера.
Output directory должен быть отдельным от дерева выгрузки; host выделяет
его только этому запросу. Пример не регистрирует raw writer, shell, сеть
или другие инструменты рядом с wrapper. Библиотека не может запретить
постороннему агенту обход через независимо выданные инструменты.

## Предложение модели и проверка

Ожидается строго JSON-объект с пятью полями:

```json
{
  "operation": "exported_functions",
  "module_id": "<host-selected module id>",
  "source_id": "<snapshot id from context>",
  "evidence": [
    {"fact_id": "<fact id>", "start_line": 1, "end_line": 3}
  ],
  "report": {"function_names": ["Real"]}
}
```

Для `returned_string` отчёт имеет единственный ключ `query` со строкой.
Никаких `path`, `system`, `trusted`, разрешений или новых полей. Имена,
ссылки и литералы остаются данными. Полная структура инструмента клиента
должна соответствовать этой операции, а инструкция передаётся отдельно.

`validate_report_action(contract, arguments, *, current_bytes)` возвращает
`ValidationResult(allowed, reason, canonical_report)`. Текущие байты читает
host, их нельзя принимать из аргументов модели. Валидатор:

1. Сверяет текущий хеш с зафиксированными байтами.
2. Заново извлекает факты из host snapshot, не доверяет переданной описи.
3. Проверяет точную операцию, module/source id и строгие ключи/типы.
4. Требует весь набор evidence с точными fact id и диапазонами, без
   дубликатов/чужих ссылок/булевых номеров строк.
5. Сверяет полный набор экспортных имён, без пропусков, лишних значений и
   дубликатов. Порядок предложения допустим любой; сохраняется порядок
   источника. Регистр/Unicode имён не переименовываются. Настоящее имя
   `DEMO_OVERRIDE` разрешено.
6. Для литерала требует точного значения, включая текст инструкций как
   данные. Конкатенация/ветвления/неподдержанное тело не разрешают действие.

При отказе `canonical_report=None`, причина — технический код без приватного
пути и исходного текста. При успехе создаётся новая каноническая JSON-строка,
а не ссылка на изменяемый объект модели. `make_report_proposal(contract)`
строит предложение детерминированно без LLM; оно тоже требует validate перед
эффектом. Его результат нельзя выдавать за устойчивость модели.

## Исполнитель и наблюдаемые эффекты

`ReportExecutor.execute_calls` принимает только один `save_report` в пакете.
Несколько вызовов из ответа отклоняются целиком **до любой записи**.
Повтор после commit отклоняется. Неверный отчёт или чужой инструмент не
создают файл. После валидации host записывает канонический результат во
временный файл, делает fsync, повторно проверяет источник и атомарно
публикует `report.json` через hard link без перезаписи существующего файла.
На файловой системе без поддержки hard links возвращается отказ записи.
Это не успешная защита/полезное выполнение задачи.

Output states: `no_report` — действий не было; `blocked_no_report` —
блокировки без нового отчёта; `correct_write` — правильный commit;
`recovered_correct` — правильный commit после блокировки. Отказ и отсутствие
отчёта не считаются полезным выполнением. Уже существующий файл не является
результатом нового запроса. `events` хранит блокировки/commit отдельно;
ошибка уборки временного файла отмечается `cleanup_failed` и не скрывает
уже совершённый commit. Причины IO санитизированы, приватные exception
messages не возвращаются модели.

## Актуальность и границы

Двойная проверка обнаруживает изменение до второго чтения, но оставляет
окно между последней проверкой и commit. Для гарантии соответствия текущему
файлу host должен эксклюзивно владеть исходной рабочей областью или обеспечить
неизменяемый снимок/синхронизацию **до завершения эффекта**. Lock примера
сериализует только его собственные вызовы; чужой процесс он не блокирует.
Хеширование, проверка symlink и frozen dataclass не являются OS sandbox.
Без этого условия отчёт соответствует зафиксированному снимку, который
может уже устареть для текущего файла. Тест явно демонстрирует этот
контрпример после последней проверки, а не объявляет гонку устранённой.

Тесты `tests/test_action_validation_issue483.py` проверяют отказ до записи,
неполноту и fault injection: изменение между проверкой и commit, ошибки
публикации/уборки, повторы и multi-call, существующее назначение. Отдельно
проверен необходимый instruction-like литерал без его исполнения.
Held-out для разработки не запускался.

Совпадение с синтаксическими фактами не доказывает правильность свободного
анализа, бизнес-смысла или произвольного патча. Произвольный patch требует
своего контракта/проверки. Строка сохранённого литерала остаётся недоверенной
для следующего потребителя. Универсальной устойчивости Qwen/Llama этот API
не обещает. Legacy/framed, CLI, исходники и старые индексы не меняются.
