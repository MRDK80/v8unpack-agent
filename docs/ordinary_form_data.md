# Данные для восстановления обычной формы

`capture_ordinary_form(extraction_root: Path, form_dir: str)` из
`v8unpack_agent.ordinary_form_data` читает одну форму из нормализованного
дерева `v8unpack.extract`. Формат проверен с saby v8unpack 1.2.13 на CF и
EPF с обычными формами версии `0-27`. Передайте относительный POSIX-путь
каталога формы внутри дерева. У исходного каталога сохраняются исходные
файлы. Для работы требуется дерево с `Configuration.json` или
`ExternalDataProcessor.json` в корне и сырые файлы формы.

Функция возвращает JSON-совместимый словарь с `schema_version` равным
`ordinary-form/1`. Поля пакета имеют следующие источники.

| Поле | Содержимое |
| --- | --- |
| `owner_kind`, `owner_uuid` | Тип CF или EPF и UUID контейнера из корневых метаданных |
| `form_dir`, `stem` | Путь и основа имён файлов формы в дереве upstream |
| `metadata` | Полный разобранный `<stem>.json` с заголовком и блоками `form` |
| `identity` | Разобранный `<stem>.id.json` с UUID формы |
| `elements` | Полный разобранный `<stem>.elem.json`, включая упорядоченные элементы, свойства, ссылки и `raw` |
| `module` | Текст `<stem>.obj.bsl` без BOM, с сохранением переносов строк |

Происхождение каждого необработанного блока определяется файлом-источником,
ключом и исходной позицией в списке. Такие блоки сохраняются в структуре.
Исходный бинарный контейнер формы в пакет не входит.
`validate_ordinary_form_data(data)` проверяет версию схемы и обязательные
поля и поднимает `OrdinaryFormDataError` при ошибке.

Пустой модуль сохраняется, а отсутствующий файл модуля вызывает ошибку.
Включаемые области `include_` и `includr_`, пустые деревья и другие форматы
форм пока вне поддерживаемого подмножества. Для полной сборки контейнера нужен
также контекст остального дерева владельца. Старые сырые выгрузки подходят,
если содержат перечисленные файлы. При наличии только `FormArtifact` и
`form_elements_index.json` требуется новое извлечение из CF или EPF.
Результаты проверки upstream описаны в [протоколе #568](research/ordinary_form_build_issue568.md).

## Восстановление файлов формы

`restore_ordinary_form(data, destination, *, element=None, right_edge=None)`
из `v8unpack_agent.ordinary_form_restore` проверяет набор и записывает
четыре файла формы в новый каталог. Родитель должен существовать. В случае
ошибки записи установленного каталога результата не будет. Для сборки
перенесите эти четыре файла в `form_dir` в копии дерева владельца и вызовите
`v8unpack.build` для всего дерева. Применяйте только к соответствующему
контейнеру `owner_kind` и `owner_uuid`.

В версии `0-27` поддерживается изменение правой границы
корневой кнопки или командной панели. Передайте ключ элемента из
`elements.data` (страница и имя через `/`, если есть страница) и координату
в единицах исходного макета. Значение должно быть больше левой границы и
не больше 32767. Правка меняет одну позицию координатного блока.
Неподдерживаемый тип, неоднозначный ключ и неизвестная форма координат
вызывают ошибку. Перекладывать произвольные позиции в массиве `raw`
в рамках этого интерфейса не требуется.

## Команда восстановления

```bash
v8unpack-agent restore-ordinary-form capture.json restored-form
v8unpack-agent restore-ordinary-form capture.json edited-form --element Main/Action --right-edge 120
```

Для запуска из дерева исходников используйте
`python -m v8unpack_agent.ordinary_form_cli restore-ordinary-form`.
Код 0 означает, что записаны все четыре файла. Код 2 означает ошибку в
аргументах, данных или правке. Код 5 означает, что каталог результата
создать не удалось. При ошибке диагностика записывается в stderr.

[Повторяемый прогон на CF и EPF и результаты приёмки](research/ordinary_form_acceptance_issue569.md).

## Структурные правки формы

Две команды принимают тот же пакет `ordinary-form/1` и записывают четыре
файла в новый каталог. Перенесите их в каталог формы в копии дерева
владельца и соберите CF или EPF через `v8unpack.build`.

```bash
v8unpack-agent add-ordinary-form-button capture.json edited-form \
  --prototype Main/OldButton --name VerifyButton --caption "Проверка" \
  --handler VerifyClick --handler-body body.bsl --vertical-offset -40

v8unpack-agent remove-ordinary-form-menu-item capture.json edited-menu \
  --panel Main/Actions --name OldItem
```

Кнопка берёт размеры и горизонтальные привязки из существующей корневой
кнопки на той же странице. Укажите смещение вверх или вниз в единицах
макета и выберите свободное место. Имя кнопки на форме и имя
обработчика должны быть новыми. Файл `body.bsl` содержит только тело новой
процедуры, например `Сообщить("Кнопка работает");`. Команда сама добавляет
объявление процедуры с параметром `Кнопка` и привязывает её к нажатию.
Поддерживаются проверенные структуры привязок версии `0-27`.

Удаление находит один пункт корневой командной панели по внутреннему
имени. Поддерживается плоский список действий. Удаляется запись показа
пункта, а определение команды и её обработчик сохраняются для других
привязок. Неоднозначные имена и неподдерживаемые шаблоны отклоняются.
