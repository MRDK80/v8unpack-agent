# Контекст результатов поиска

Библиотечный сборщик контекста результатов общего поиска (#327).
CLI-интеграция не входит в эту задачу.

## API

```python
from v8unpack_agent.search_context import build_search_context

context = build_search_context(
    dispatch,
    fragmentation,
    max_chars=12000,
)
```

`dispatch` — `DispatchResult` #326. `fragmentation` — `FragmentationResult`
#324 либо `None`. Для `semantic` отсутствие fragmentation вызывает
`ValueError`; для точного попадания отсутствие источника отражается как
`source_missing`. Входы не изменяются. Чтения файлов, сетевых запросов,
вызова эмбеддера и повторного поиска нет.

## Состояния и бюджет

`search_kind` сохраняет exact, ambiguous, semantic, empty или error.
Независимый `status`: built, truncated, insufficient_budget либо
 token_count_failed. `built` при `search_kind=error` означает только успешную
сборку сообщения об ошибке, не успешный поиск.

`max_chars=-1` снимает символьный предел; 0 даёт пустой текст с
insufficient_budget. `max_tokens` требует `count_tokens`. Оба бюджета
проверяют весь текст вместе с заголовками, координатами и предупреждениями.
Ошибки callback и результаты bool, отрицательные либо нецелые значения
дают token_count_failed, пустой text и пустой included. Текст исключения
не раскрывается. Нулевой токенный бюджет даёт insufficient_budget.

Сборщик проверяет префиксы целых строк, не предполагая монотонности
пользовательского счётчика. Для длинных источников это может потребовать
квадратичного объёма работы; этот вариант не заявляет оптимизацию O(log n).
При невозможности уместить даже сообщение возвращается пустой text;
метаданные доступны через Python API.

## Источник и происхождение

Используется только `SearchDocument.text`, никогда `search_text`.
Точное попадание собирает фрагменты того же артефакта в порядке строк;
смысловое — только исходный `document_id` попадания. Перекрывающиеся строки
объединяются один раз; конфликт текста или координат даёт source_mismatch.
Разрывы координат не заполняются придуманным текстом.

`source_document_ids` сохраняет исходные id, а `included_span` описывает
реально включённый диапазон. Частичный фрагмент не получает новый
вымышленный document_id. Документ без span атомарен: полный текст либо
no_span_atomic. Невместившийся строковый префикс отмечается line_too_long.
Источник уже должен быть нормализован #324; некорректные BOM/CR в
позиционированных фрагментах отклоняются, координаты не пересчитываются.

## Неопределённость

Ambiguous выдаётся списком альтернатив без выбора и без подстановки
исходного кода одного кандидата. `top_k` не сокращает этот список.
В тексте и модели есть candidates_shown, candidates_total и
candidates_omitted; бюджет может ограничить количество показанных карточек.

Сохраняются path, index_status, exact_filtered_out, method, matched_field
и similarity. Similarity не называется вероятностью правильности.
OwnerLink выводится вместе с basis и confirmed; unconfirmed не повышается
до подтверждённой связи. Для semantic без index_status это явно отмечено.
Проверка актуальности индекса не повторяется: сборщик сохраняет переданные
диспетчером свидетельства, но не подтверждает их самостоятельно.

## Сериализация

Схема `search_context/1`: `to_dict()` и детерминированный `to_json()`
не включают текст источников и итоговый text по умолчанию; требуется
`include_text=True`. Метаданные артефактов и запрос из DispatchResult
могут быть чувствительными: сериализация не является обезличиванием.
`from_dict` в scope не входит. Экспорт из корневого __init__ не меняется.
