# Обычные формы 0-5-1 и источник статической описи (#541)

Для 54 записей `0-5-1` из выборки C сопоставили UUID с отдельной выгрузкой
Конфигуратора. Все 54 UUID найдены. У каждой записи есть `Ext/Help.xml` и
HTML-страница справки. `Ext/Form.bin` и `Ext/Form.xml` отсутствуют у всех 54.

Base64 из `metadata.form[0][0][3][0]` декодируется как UTF-8 HTML.
Последовательность текстовых фрагментов с нормализацией пробелов совпала со
страницей `Ext/Help/*.html` у всех 54. Сравнение выполнено без открытия
страниц в браузере. Содержимое справки не устанавливает список объявлений
реквизитов или их порядок. Пустой `props` и заключительный `0` сами по себе
не подтверждают пустую опись.

| Результат проверки | Количество |
| --- | ---: |
| Записи `0-5-1` | 54 |
| Совпадение UUID и текста справки | 54 |
| Файлы `Form.bin` или `Form.xml` | 0 |
| Подтверждённые новые описи | 0 |
| `unsupported:form_kind_or_version_unsupported` | 54 |

На трёх прежних выгрузках при аудиторском лимите 10 МБ повтор получился
идентичным #539. Все 5959 прежних полных описей совпали по порядковому
номеру и хэшу отчёта. Из 6030 записей остаются 54 неподдержанные, 13
неполных и четыре без исходного корня. Аудит выполнялся локально без
модели. Продуктовый статус формата остался прежним.

Сравнение повторяется из корня checkout с установленным пакетом:

```bash
python scripts/audit_form_help_issue541.py UNPACKED_EXPORT DESIGNER_EXPORT
```

Первый аргумент — распаковка v8unpack, второй — выгрузка той же
конфигурации через Конфигуратор. Скрипт выводит агрегаты. Для повторного
аудита A/B/C используйте [процедуру #539](form_coverage_issue539.md).
Для допуска формата нужен независимый источник, который подтвердит
объявления или их отсутствие. В двух обследованных представлениях
доступна только справка и описание объекта.
