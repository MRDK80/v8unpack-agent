# Ограниченный data flow: эксперимент #216

Проверен приватный прототип B0, расширяющий linker #215 доказанными
аргументами локального вызова. Порог качества не достигнут. B0 не входит
в production API; интеграция #217 использует linker #215. Это решение
отложить проверенный вариант, а не доказательство бесполезности любого
внутримодульного data flow.

## Зафиксированный эксперимент

A — реализация #215, merge `2e018bfed92139461d94f6cbe11b8396ff09c3b7`.
Закрытый scope, исходники, аннотации и primary endpoint зафиксированы до B.
Основной gold — 31 полностью размеченный модуль, 420 операций, из них
364 входят в MVP. Единица прежняя: вид операции и строка метода/знака
присваивания. Несколько предсказаний одной единицы не добавляют TP.
Unresolved не считается подтверждённой операцией. Raw-канал детектора
сохраняется отдельно и не подменяет bound endpoint после измерения.

Принятые инженерные пороги:

- Устранить ≥20% FN A: при 282 FN это минимум 57 нетто.
- Получить ≥20 дополнительных TP суммарно, с приростом минимум в двух
  конфигурациях.
- Потерять не более 0,5 процентного пункта precision.
- Уложиться в 2× wall time и peak RSS A на каждой конфигурации.
- Разобрать все новые FP, утраченные TP и новые доказательства идентичности.

B0 переносит exact-аргумент текущей формы, декларативного элемента или
коллекции элементов/команд в параметр известной процедуры того же модуля.
Параметры должны пройти консервативную проверку записи и передачи дальше.
Рекурсия не раскрывается; максимум 16 выбранных контекстов на модуль.
Один детерминированно выбранный свидетель вызова относится только к этому
контексту. Он не означает одинаковый аргумент у всех runtime-вызовов.

Выражение вызова сохраняется как guard с неизвестной runtime-истинностью;
точность ссылки ограничена этим контекстом. Неизвестное изменение namespace
в caller сохраняет unresolved у поиска декларативного элемента. Ссылки на
динамические создания не переносятся между процедурами в обход валидатора
#213. Нет выполнения BSL, раскрытия общих модулей или запуска моделей.

B0 не реализует перенос скалярных литералов, CFG join и общую модель
эффектов. Сохранение ссылки на форму в цикле само по себе не доказывает
сохранность именованного элемента. Первоначальное более сильное ожидание
в синтетическом loop-примере не подтвердилось; ограничение сохранено,
прототип после начала измерения не менялся.

## Качество

| Корпус | Gold MVP | A TP / FP / FN | B0 TP / FP / FN | Новые TP |
|---|---:|---:|---:|---:|
| C1 | 82 | 2 / 0 / 80 | 3 / 0 / 79 | 1 |
| C2 | 30 | 1 / 0 / 29 | 2 / 0 / 28 | 1 |
| C3 | 187 | 73 / 0 / 114 | 73 / 0 / 114 | 0 |
| C4 | 65 | 6 / 0 / 59 | 11 / 0 / 54 | 5 |
| Всего | 364 | 82 / 0 / 282 | 89 / 0 / 275 | 7 |

Устранено 7/282 = 2,48% FN при требовании ≥20%; 7 новых TP меньше 20.
Прирост в трёх конфигурациях проходит отдельный критерий; три модуля
с приростом имеют разные байтовые SHA, прирост не получен повторным
подсчётом одинаковых файлов. Новых FP и
утраченных TP в этом gold нет. Все семь новых сайтов проверены отдельно:
свидетель локального вызова передаёт текущую форму, целевое имя имеется
в декларативном инвентаре, ссылка ограничена guard вызова/ветви. Проверка
сайта операции и проверка идентичности — разные проверки.

Наблюдаемый precision на gold равен 100% у обеих версий; это не оценка
precision всего корпуса. Bound recall вырос с 22,53% до 24,45%.
Отдельный raw-регрессионный baseline #214 — 250 TP / 0 FP / 114 FN;
он не является альтернативным primary endpoint этого эксперимента.

Дополнительно до просмотра предсказаний полностью размечены 12 модулей:
по два исходно probe-positive и одному probe-zero на конфигурацию.
Фиксированная выборка исключает прежние 31 модуль и совпадающие байтовые
SHA; выбранные модули также попарно различны по SHA. Всего 1573 строки,
28 операций, 18 MVP. У A и B0 одинаково 4 TP / 0 FP / 14 FN.
Это вторичная проверка; она не меняет основной denominator и порог 57.

Разметку выполнял один ассистент, независимого эксперта нет. Основной набор
использовался при разработке и является regression gold. Дополнительная
выборка стратифицирована по прежнему пробнику и не является случайной
оценкой популяции. Конфигурации имеют разные корневые идентификаторы,
но разделяют библиотечный код; статистическая независимость не заявляется.
Десять синтетических сценариев проверены дважды: доказанный/неизвестный
аргумент, локальная копия, запись/escape параметра, непрозрачный вызов,
рекурсия, условный вызов и консервативный цикл.

## Стоимость и повторяемость

Выполнены восемь fresh-process проходов: два на каждой из C1–C4,
с теми же подготовленными входами и проверкой SHA исходников. В каждой
паре совпали хеш результата, счётчики, отказы и диагностика. Исходники
прототипа перед/после сверены с зафиксированными хешами. Повторная
проверка полных манифестов подтвердила неизменность 141 912 файлов.

| Корпус | B0 wall, с (1 / 2) | B0 peak RSS, МиБ (1 / 2) | Wall / A | RSS / A |
|---|---:|---:|---:|---:|
| C1 | 45.169 / 44.810 | 92.4 / 92.7 | 1.68 | 1.03 |
| C2 | 11.576 / 11.462 | 37.0 / 36.9 | 1.59 | 1.03 |
| C3 | 1.838 / 1.816 | 32.4 / 32.3 | 1.56 | 1.02 |
| C4 | 517.993 / 515.823 | 227.8 / 227.4 | 1.71 | 1.05 |

Отношение консервативное: максимум двух B0 / минимум двух A.
Linux, Python 3.12.3; границы wall/RSS соответствуют [замеру A](dynamic_forms_issue215.md).
B0 вычисляет индекс A и дополнительный проход доказательств; хешируется
его индекс операций. Это стоимость приватного прототипа, без production
сборки новых кандидатов B. A сериализовал полный binding index, B0 — индекс
операций, поэтому отношения не являются гарантией стоимости будущего
интегрированного data flow и не заменяют его отдельный cost gate.
Отказ по качеству не зависит от этой оговорки.

Успешные модули/отказы сохранены: C1 805/7, C2 236/9, C3 51/1,
C4 5798/105. Дополнительные подтверждения полного корпуса: 62, 15, 0,
533 соответственно. Это **не TP**, их population precision не измерен.
Они не используются вместо gold для прохождения порога.
[Обезличенные агрегаты](dynamic_forms_issue216_aggregates.json) содержат
хеши входов/результатов, счётчики и диагностику без имён, путей и BSL.

## Решение и отложенный остаток

B0 не проходит quality gate независимо от стоимости и не переносится в
production. Схема #213 и linker #215 не ослабляются ради восстановления
старых raw TP. В #217 используется A, с явными unresolved и отказами;
метрики #218 должны сохранять этот консервативный остаток.

Перенос литералов, CFG-анализ ветвей, доказанные эффекты локальных вызовов,
инварианты циклов и более широкие контексты параметров остаются отложенными.
Их совокупный эффект этим B0 не измерен. Новый эксперимент должен заранее
зафиксировать классы, gold, proof-контракт и baseline, проверить качество
идентичности отдельно от наличия операции и повторить принятые пороги.
При недостаточном релевантном gold решение по новому классу остаётся
открытым. Межмодульный анализ по-прежнему вне MVP.

Невыполненные критерии реализации #216 не отмечаются как выполненные:
зафиксирован эксперимент и условное откладывание feature по графу #211.
Полный принятый data flow не заявляется реализованным.
