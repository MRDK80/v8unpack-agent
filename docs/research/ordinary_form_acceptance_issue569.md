# Приёмка обратной сборки обычных форм (#569)

Проверены saby v8unpack 1.2.13 и 1С:Предприятие 8.5.4.1291 (учебная
версия, Linux x86-64). Поддержанное подмножество — обычные формы
`0-27` из CF и EPF с полными сырыми файлами без включаемых областей.
[Состав пакета и ограничения](../ordinary_form_data.md).

## Воспроизводимый прогон

Извлечь пакет формы из нормализованной выгрузки. `OWNER` указывает на
синтетический CF или EPF, `EXTRACTED` — на новый каталог, `FORM_DIR` —
на относительный каталог формы в нём, `CAPTURE` — на новый JSON-файл.

```bash
python - "$OWNER" "$EXTRACTED" "$FORM_DIR" "$CAPTURE" <<'PY'
import json
import sys
from pathlib import Path

from v8unpack.v8unpack import extract
from v8unpack_agent.ordinary_form_data import capture_ordinary_form

owner, extracted, form_dir, capture = sys.argv[1:]
if Path(extracted).exists():
    raise SystemExit("Use a new directory for extraction")
extract(owner, extracted, processes=1, options={"auto_include": False})
with Path(capture).open("x", encoding="utf-8") as output:
    json.dump(capture_ordinary_form(Path(extracted), form_dir), output, ensure_ascii=False)
PY
```

Выполнить первый прогон без правки и второй с новым значением правой
границы. `ELEMENT` — ключ корневой кнопки или командной панели в
`elements.data`. `RIGHT_EDGE` — новая координата в единицах макета.

```bash
v8unpack-agent restore-ordinary-form "$CAPTURE" "$RESTORED"
v8unpack-agent restore-ordinary-form "$CAPTURE" "$EDITED" --element "$ELEMENT" --right-edge "$RIGHT_EDGE"
```

Для каждого прогона подготовить отдельный новый `BUILD_TREE`. В аргументе
`FORM_FILES` указать каталог `RESTORED` или `EDITED`. Расширение
`BUILT_OWNER` должно соответствовать исходному контейнеру.

```bash
python - "$EXTRACTED" "$BUILD_TREE" "$FORM_DIR" "$FORM_FILES" "$BUILT_OWNER" <<'PY'
import shutil
import sys
from pathlib import Path

from v8unpack.v8unpack import build

original, tree, form_dir, files, result = sys.argv[1:]
shutil.copytree(original, tree)
for source in Path(files).iterdir():
    shutil.copyfile(source, Path(tree) / form_dir / source.name)
build(tree, result, processes=1, options={"auto_include": False})
PY
```

Встроенную форму проверить после `/LoadCfg` и `/UpdateDBCfg` в обычном
приложении в отдельной временной базе. EPF открыть через `/Execute`
в той же временной базе. Для контроля состояния после открытия форму
закрыть без сохранения изменений.

### Повторное извлечение

Для EPF повторить `v8unpack.extract` с теми же параметрами в новом
каталоге `REEXTRACTED`. Сравнение проверяет UUID, полный нормализованный
документ элементов и модуль. Порядок в массивах и каждый элемент
`raw` участвуют в сравнении. Форматирование JSON и BOM модуля
исключены из сравнения. Для прогона с правкой передать те же
`--element` и `--right-edge`.

```bash
python -m scripts.verify_ordinary_form_roundtrip_issue569 normalized "$EXTRACTED" "$REEXTRACTED" "$FORM_DIR"
```

Для CF с двумя контейнерами прямое повторное извлечение в этой версии
upstream останавливается до разбора формы. Использовать
`/DumpConfigToFiles` до и после сборки и сравнивать составляющие
`Form.bin` из этих двух выгрузок. Здесь исходный бинарник служит
только контрольным входом компаратора. Проверяется весь разобранный
макет с сохранением порядка и значений. В модуле сравнивается весь текст
с нормализацией UTF-8 BOM и переводов строк. Пробелы, пустые строки и
регистр участвуют в сравнении.

```bash
python -m scripts.verify_ordinary_form_roundtrip_issue569 designer "$BEFORE_FORM_BIN" "$AFTER_FORM_BIN"
```

Для прогона с правкой задать `--coordinate-path` с индексами позиции
в разобранном макете и `--right-edge` с ожидаемым значением.
На выбранном CF позиция правой границы была `0 1 2 2 1 3 3`.
Скрипт возвращает 0 при совпадении и 1 при расхождении.

## Результат синтетической приёмки

| Образец | Без правки | С правкой |
| --- | --- | --- |
| CF, обычная форма элемента справочника | Собран и загружен, форма открылась; пять модулей и пять разобранных макетов эквивалентны | Форма открылась; правая граница выбранной кнопки изменилась с 206 до 196. Остальные значения макета и модуль совпали; четыре соседние формы совпали полностью |
| EPF, обычная форма с командными панелями | Собран и прочитан Конфигуратором, форма открылась в обычном приложении; модуль и нормализованная структура эквивалентны | Форма открылась; правая граница панели изменилась с 400 до 390. В повторно извлечённом нормализованном дереве сохранились остальные значения и модуль |

Выгрузки EPF через Конфигуратор содержат расхождения в низкоуровневом
макете даже между контрольными прогонами. Для EPF подтверждена
эквивалентность нормализованного представления. Для CF совпадение
проверено по разобранному макету из выгрузки Конфигуратора.
[Протокол и локализация проблем upstream](ordinary_form_build_issue568.md).

## Контрольные прогоны на реальных выгрузках

Выборка взята после синтетических прогонов. Из доступных компактных выгрузок
взяты один CF с обычными формами встроенных обработок и семь EPF различного
размера. Два EPF исключены после классификации, поскольку в них нет обычных
форм. Из каждого оставшегося владельца взята первая обычная форма по
относительному пути upstream. Это шесть выбранных форм, включая формы с
командными панелями, страницами, полями и таблицами. Сборка проводилась на
копиях, без изменения свойств. Проверка открытия выполнена в редакторе
форм Конфигуратора в отдельной тестовой базе.

| Случай | Сборка и открытие | Повторное извлечение |
| --- | --- | --- |
| Один CF | CF принят Конфигуратором, выбранная форма открылась | Прямое извлечение остановилось на оглавлении контейнера. После XML-выгрузки Конфигуратором все шесть обычных форм совпали по полному разобранному макету и тексту BSL. В пяти модулях различались только переводы строк |
| Пять EPF | Все пять EPF приняты Конфигуратором, все выбранные формы открылись | Прямое повторное извлечение успешно. Модуль, UUID и полное нормализованное дерево совпали у пяти из пяти выбранных форм |

Итого шесть из шести выбранных форм прошли сборку, открытие в редакторе
и сравнение. Для CF понадобилась повторная выгрузка в 1С. Исполнение
реальных модулей и их обработчиков в режиме предприятия в эти прогоны
не входило. Тестовая выборка ограничена проверенными версиями платформы,
приведёнными видами владельцев и форматом `0-27`.
