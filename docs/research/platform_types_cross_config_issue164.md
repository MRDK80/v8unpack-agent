# Кросс-конфигурационная проверка платформенных типов (#164)

> Статус: **скелет отчёта**. Разделы 4–10 заполняются только после прогона на
> двух независимых выгрузках. Пока второй выгрузки нет, вывод не формулируется
> и PR не создаётся — прямое ограничение issue #164.
>
> Обезличенность: UUID, короткие хэши, имена конфигураций, объектов, форм,
> реквизитов, организаций, локальные пути и строки подключения в документ не
> попадают. Элементы пересечения обозначаются рангами `P01…Pnn`; таблица
> `Pxx → UUID` остаётся в памяти процесса или в локальном игнорируемом файле.

## 1. Цель и граница доказательства

Проверяется гипотеза: UUID класса `reference_only` — стабильные идентификаторы
типов, объявляемых платформой, а не объекты конкретной конфигурации.

Доказывается платформенная природа конкретных UUID. **Не** доказывается имя
типа: выводить имя из имени соседнего реквизита, частоты, вида формы, позиции
рядом с известным типом или прикладной логики запрещено (#165 требует отдельного
авторитетного доказательства имени).

Критерий: одни и те же UUID входят в `reference_only` обеих выгрузок, позиция
определения отсутствует в обеих, позитивный контроль детектора валиден в обеих
(coverage >= 90%).

## 2. Критерий независимости конфигураций

- независимая типовая конфигурация другой продуктовой семьи;
- отличается составом и количеством прикладных объектов;
- по возможности другой релиз конфигурации;
- не копия, не расширение и не производная от A;
- выгрузка выполнена отдельно.

## 6. Пересечение reference_only

Сравнивается только `A_reference_only ∩ B_reference_only`. Весь `unresolved` не
сравнивается: `definition_known` и другие классы имеют установленную природу.
Заполняется после прогона: `|A|`, `|B|`, `|A ∩ B|`, `|A − B|`, `|B − A|`.

## 7. Покрытие вхождений

Вхождения A и B, покрытые пересечением, их доли от `reference_only`-вхождений и
от всех применимых Ref-вхождений каждой выгрузки.

## 8. Разности A-only / B-only

Поэлементные вердикты: `confirmed_for_intersection`, `not_confirmed_A_only`,
`not_confirmed_B_only`, `contradicted_by_definition`, `insufficient_evidence`.

## 9. Проверка отсутствия определений

Для каждого элемента пересечения: класс `reference_only` в A и B, кандидатов
определения 0 в A и B, контроль валиден в A и B, UUID отсутствует в
`reference_types` обеих выгрузок.

## 10. Итог по гипотезе

`подтверждена` (только для пересечения) / `частично подтверждена` /
`опровергнута` / `данных недостаточно`. Нулевое пересечение двух разных релизов
платформы само по себе гипотезу не опровергает: фиксируется
`insufficient_evidence`, а не догадка.

## 11. Влияние на #165

#165 разблокируется только в объёме подтверждённого пересечения. A-only, B-only
и UUID с найденным определением в таблицу не попадают. Совпадение UUID между
конфигурациями разрешает считать запись платформенной, но не разрешает подписать
её предположительным именем.

## 12. Обезличенность и воспроизводимость

Компаратор: `examples/reference_only_compare.py` — чистый stdlib-модуль без
зависимостей от `v8unpack_agent`. Агрегаты одной выгрузки собирает
`from_residual(...)` из структур `examples/unresolved_refs_report.py`
(остаток, контрольная группа, слоты идентичности, индекс типов).

Самопроверка без выгрузок:

```
python examples/reference_only_compare.py --selftest
python -m pytest -q tests/test_platform_types_cross_config_issue164.py
```

Контроли компаратора: A против A (пересечение полное, разности пустые, покрытие
вхождений 100%); синтетически непересекающиеся множества; смена класса
`reference_only` → `definition_known` (в пересечение не попадает); UUID,
попавший в индекс типов; провал контроля B (exit code 2); недетерминированный
прогон (exit code 3); детерминированность рангов и отсутствие UUID в публичном
выводе (`anonymity_guard`, exit code 4 при утечке).

Выгрузки, annex и CSV в репозиторий не добавляются. Локальные режимы
`--local-names` и `--annex` в issue и PR не используются.
