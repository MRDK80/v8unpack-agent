# Нессылочные типовые грани и виды метаданных без ссылочной формы (issue #166)

<!-- REPORT-VERSION: FINAL-v2 -->

- Ветка: `research/166-non-reference-type-facets`, база `2d8e488`
- Предшественники: #143, #164 (PR #174), #167 (PR #178), #168 (PR #177)
- Вердикт: **keep_unresolved**; по структурной части — **need_more_evidence**
- Production-код не изменён, `REFERENCE_TYPE_PREFIXES` не расширен, fallback `Ref#uuid` сохранён

## 1. Цель и граница доказательства

Проверялось, существует ли доказуемый контракт «вид метаданных × нормализованный слот → имя типовой грани» для класса `definition_known` (#143), без расширения `REFERENCE_TYPE_PREFIXES`.

Требовались два независимых доказательства:

- **A — структурная стабильность слота**: существование в обеих выгрузках, одна нормализованная позиция, не более одного вхождения на объект, отсутствие другой роли внутри вида, несовпадение с доказанной ссылочной гранью, независимость от числа слотов в файле и от имени объекта.
- **B — семантическое имя грани**: документированный формат raw-header, авторитетная документация платформы, контролируемая синтетическая конфигурация, воспроизводимый платформенный API/сериализация либо иное структурное доказательство без опоры на имена соседних реквизитов.

Наличие только A даёт `slot_stable_name_unknown`; отсутствие пары во второй выгрузке даёт `single_config_only`. Псевдоимена (`DocumentFacet7.<Object>`, `UnknownFacet.<Object>`, `MetadataSlot7.<Object>`) и автосборка `ReportRef.<Name>`, `DataProcessorRef.<Name>`, `InformationRegisterRef.<Name>`, `DocumentJournalRef.<Name>` исключены.

## 3. Метод определения identity/header-позиций

Слот идентичности выводится из позитивного контроля, а не назначается вручную. В обеих выгрузках выведен один профиль:

```
object_metadata | bare | header/*/*/*   покрытие 100.0%   попаданий/uuid 1.00
```

Роль файла определяется структурно: в A `object_metadata` 3920, `object_other` 13572, `config_other` 3; в B — 107 / 469 / 1. Класс `definition_unknown_layout` пуст в обеих выгрузках. В B дополнительно наблюдался профиль `object_metadata|bare|header/*/*/*/*/*` с покрытием 12.8% и нулём UUID остатка — как источник кандидатов не использовался.

Наблюдения по стабильности внутри A:

Разбивка вхождений внутри подгруппы «вид вне таблицы префиксов» (Report 80, DocumentJournal 16, InformationRegister 5, DataProcessor 2) восстановлена из ранговых счётчиков прогона и состава видов #143; суммы сходятся точно (103). При повторной проверке per-kind распределение следует выводить инструментом напрямую, а не реконструировать.

## 8. Доказательства или отсутствие доказательств имён

Доказательство B не получено ни для одной пары:

- документированного формата raw-header с нумерацией слотов в публичном доступе нет;
- документация платформы описывает ссылочные, объектные и менеджерские типы на уровне встроенного языка, но не связывает числовой слот файла выгрузки с гранью;
- контролируемая синтетическая конфигурация не строилась, а для видов без ссылочной формы этот путь частично закрыт: значения соответствующего типа не существует;
- имена соседних реквизитов как источник запрещены границей доказательства.

Итог: `slot_stable_name_proven` — 0 пар.

## 10. Иные типовые грани индексированных объектов

10 UUID / 55 вхождений в четырёх видах из таблицы префиксов. Во всех случаях ссылочная грань объекта уже проиндексирована (1 или 3 слота в индексе), а спорный UUID стоит в отдельном слоте того же файла. Совпадений с доказанной ссылочной гранью нет, перезаписи `reference_types` не потребовалось бы. Имя грани не доказано, поэтому реализация не допускается.

## 11. Риски ложноположительной резолюции

- Слот 1 у видов без ссылочной формы численно совпадает с позицией доказанной ссылочной грани у ссылочных видов: вывод имени по номеру дал бы ложное `Ref.<Имя>`.
- `(BusinessProcess, 5)` и `(Task, 5)` совпадают по номеру при разных видах — общее имя для номера ничем не обосновано.
- Все пары наблюдаются в одной конфигурации: контракт, выведенный по A, был бы привязан к одному релизу и одной продуктовой семье.
- Имена реквизитов рядом со спорным UUID выглядят подсказкой, но их использование запрещено границей доказательства.

## 14. Условия пересмотра

1. Третья выгрузка с непустым `definition_known`, дающая пересечение пар с A.
2. Контролируемая синтетическая конфигурация с независимо доказанной гранью слота.
3. Документированный формат raw-header либо авторитетная документация слотов.
4. Платформенный API или сериализация, возвращающие имя для того же UUID.

## 15. Обезличенность и воспроизводимость

- В публичный вывод не попали UUID, имена конфигураций, объектов, форм, реквизитов и абсолютные пути; локальные срезы получены через `--local-names` и `--annex` во временный каталог вне репозитория, CSV не коммитился.

- Полный `pytest` — 917 passed. Линт: в `examples/unresolved_refs_report.py` остаются два предсуществующих замечания (`EXE001`, `SIM114`), новых не добавлено; долг передан в #161.
