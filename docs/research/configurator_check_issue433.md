# Сверка необработанных BSL-файлов с Конфигуратором (issue #433)

Исследование эпика #431. Для каждого шаблона из остатка #432
([`bsl_remainder_issue432.md`](bsl_remainder_issue432.md)) установлено,
каким модулем Конфигуратора он является. Выгрузки только читались.

## Источники

- Файлы `v8unpack` — те же выгрузки E3 и E5, что в #432.
- Эталон для E3 — выгрузка той же конфигурации Конфигуратором в файлы
  (XML, иерархическая), сделанная владельцем: модули в ней лежат под
  именами вида (`Ext/ObjectModule.bsl`, `Ext/ManagerModule.bsl`,
  `Ext/RecordSetModule.bsl`), их записывает сама платформа.
- Эталон для E5 — текст модулей расширения, скопированный владельцем из
  окна модуля Конфигуратора (в учебной версии «Сохранить как» для модуля
  недоступно).

Перед XML-выгрузкой конфигурация E3 была снята с поддержки, и владелец
добавил отсутствовавшие модули с одной строкой-комментарием. Такие модули
в выгрузке `v8unpack` не существуют и в сверке дают несовпадение; каждый
из них проверен: ровно одна непустая строка, комментарий.

## Результат

| Шаблон | Где | Число | Совпал с | Тип совпадения | Вердикт |
|---|---|---:|---|---|---|
| `AccountingRegister/{N}/AccountingRegister.obj.bsl` | E3 | 1 | модуль набора записей | после снятия BOM и CRLF → LF байты равны | `record_set` |
| `ChartOfAccounts/{N}/ChartOfAccounts.obj.bsl` | E3 | 1 | модуль объекта | то же | `object` |
| `ChartOfCalculationTypes/{N}/ChartOfCalculationTypes.obj.bsl` | E3 | 1 | модуль объекта | то же | `object` |
| `Sequences/{N}/Sequences.obj.bsl` | E3 | 3 | модуль набора записей | по структуре; 2 пустых файла совпали с пустыми модулями | `record_set` |
| `ConfigurationExtension.app.bsl` | E5 | 1 | модуль приложения расширения | текст равен после снятия BOM, CRLF и концевых пробелов | `managed_application` |
| `ConfigurationExtension.ssn.bsl` | E5 | 1 | модуль сеанса расширения | то же | `session` |

Вердикт — существующий `module_kind` контракта `docs/modules.md`;
`owner_kind` для E3 — `metadata_object`, для E5 — см. ниже.

Подробности:

- **Модуль менеджера** регистра бухгалтерии, плана счетов и плана видов
  расчёта в выгрузке `v8unpack` отсутствует (добавлен владельцем после
  выгрузки) и ни с одним файлом не совпал. Файл `{Type}.obj.bsl` у этих типов — не менеджер.
- **Регистр бухгалтерии** не имеет модуля объекта, план счетов и план
  видов расчёта — модуля набора записей (ограничение платформы,
  подтверждено владельцем в Конфигураторе). Поэтому кандидатов было по
  два, и совпал ровно один.
- **Последовательность** в XML-выгрузке имеет только `RecordSetModule.bsl`
  (модуля менеджера и модуля объекта нет), поэтому `Sequences.obj.bsl` —
  модуль набора записей. Это подтверждает и текст: два файла `v8unpack`
  пустые и совпали с пустыми модулями; третий (`whitespace_only`, один
  перевод строки) отличается только добавленным владельцем комментарием.
  Текстового совпадения непустого модуля последовательности на этих данных
  нет — это ограничение доказательства.
- **Расширение:** Конфигуратор показывает у расширения один «Модуль
  приложения» без деления на обычное и управляемое; модулей внешнего
  соединения и обычного приложения нет. Перекрёстные пары (модуль
  приложения против модуля сеанса) не совпали.

## Нормализация `v8unpack`

На трёх непустых модулях E3 файл `v8unpack` побайтно равен модулю
Конфигуратора после двух преобразований: снят BOM UTF-8 и CRLF заменён на
LF. Концевые пробелы и пустые строки не менялись. Это расходится с
формулировкой #351 «побайтно»: там эталоном был текст, сохранённый из окна
модуля, без сравнения BOM и переводов строк.

## Выводы для #434 и #435

- E3: `AccountingRegister.obj.bsl` и `Sequences.obj.bsl` — `record_set`
  (как у `AccumulationRegister`/`InformationRegister`);
  `ChartOfAccounts.obj.bsl` и `ChartOfCalculationTypes.obj.bsl` —
  `object`. Пары `metadata_type`/`module_kind` для этих типов подтверждены
  только на одной выгрузке (E3).
- E5: `.app.bsl` и `.ssn.bsl` с префиксом `ConfigurationExtension` —
  модуль приложения и модуль сеанса расширения. Выбор между
  `owner_kind` `configuration` и `extension` для них и для остальных
  модулей расширения — решение #435.
- Неподтверждённых шаблонов не осталось; модули менеджера этих типов не
  встретились ни в одной выгрузке `v8unpack` и записей не получают.
