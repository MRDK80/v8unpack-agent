# Поисковое представление форм и модулей и синтетический eval-набор (issue #321)

Исследование для эпика #320. Production-код, публичные API, CI и схемы не менялись.
Машиночитаемые наборы: [`search_eval_issue321.json`](search_eval_issue321.json) (базовый) и
[`search_eval_issue321_hard.json`](search_eval_issue321_hard.json) (усиленный, дополняет базовый).

## Границы

Корпус и запросы синтетические. Результаты не описывают качество поиска на реальных
конфигурациях. Fake- и hash-эмбеддеры доказывают только механику, не релевантность.
Платные запуски и провайдерный SDK не использовались; реальный код никуда не передавался.

## Единицы поиска

| Единица | Идентичность | Источник |
|---|---|---|
| Модуль | `<owner_kind>:<metadata_type>:<owner_name>:<module_kind>` | `ModuleEntry` (#203) |
| Форма | `form:<object_type>/<object_name>/<container_name>/<form_name>` | 4-кортеж `FormRagIndex` |
| Фрагмент | `<id артефакта>#<процедура>`; без процедур — `<id>#L<начало>-<конец>` | предложение для #322/#324 |

В `ModuleEntry` нет синонима владельца. Синоним — требование к карточкам владельцев (#323), а не готовый вход.
Модуль с `read_status` `empty` и `whitespace_only` в индекс текста не входит, `missing` означает «файла нет».

## Текст документа

Заголовок `MODULE / kind / owner_kind / metadata_type / owner / синоним`, затем тело.
Слитные идентификаторы разбиваются по смене регистра (`РеализацияТоваров` → «Реализация Товаров»).
Точный поиск по имени и `form_name` выполняется вне эмбеддера, сравнением нормализованных строк.

## Эталон и классы запросов

Эталон — множество id артефактов (и фрагментов), не наличие слова. Классы: exact, free, ambiguous, negative, mixed.
В корпусе все 12 `module_kind`, формы, `object` внешней обработки и отчёта. Unresolved-виды (`Sequences`, `obj`
у `ChartOfAccounts`, `ChartOfCalculationTypes`, `AccountingRegister`) есть только в отрицательных запросах.

Усиленный набор добавляет теги запросов: `paraphrase` (нет общих основ слов с целевой процедурой, проверяется
тестом), `tail` (целевая процедура после первых `max_chars` тела) и `distractor` (рядом артефакт с близкими
именем или словами). Базовые запросы в метриках помечены `base`.

## Протокол метрик

Статус: согласовано владельцем в чате #321 (2026-10-06); в GitHub не записано до этого PR.

- Exact: accuracy@1 = 1.0; ambiguous — полное множество кандидатов и статус неоднозначности; ложных exact на negative — 0.
- Semantic: hit@1, recall@5, mrr@10, ndcg@10 по артефактам; агрегация max по фрагментам, дубли удаляются.
- Пороги для free: recall@5 ≥ 0.80, mrr@10 ≥ 0.60.
- Фрагменты выбираются, если recall@5 не хуже целого модуля более чем на 0.05 и лучше на больших телах.
- Negative: только распределение сходства, порога отказа нет.

## Эмбеддер и воспроизведение

Вариант B: лексический baseline (BM25 по основам из пяти символов) и локальная `multilingual-e5-small`.

| Параметр | Значение |
|---|---|
| Модель | `intfloat/multilingual-e5-small`, ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3` |
| Библиотеки | sentence_transformers 6.1.0, transformers 5.17.0, torch 2.14.0+cu130 |
| Устройство, сеть | CPU, прогон без сети (модель из локального кэша) |
| `max_chars` | 2000 на документ; `max_seq_length` 512 |
| Префиксы | `query: ` для запроса, `passage: ` для документа |
| Сходство | косинус нормализованных векторов |

Замер выполнен локальным скриптом владельца, который в репозиторий не входит. Метод полностью описан выше;
повторить результат можно по этим параметрам и двум наборам.

## Результаты прогона

Корпус: 21 артефакт, 42 запроса; метрики посчитаны на 23 запросах free и mixed. Exact-часть: accuracy@1 8/8,
неоднозначные 4/4, ложных exact на negative 0/7. Лимитом `max_chars` усечены 2 документа из 21.

Первый прогон только на базовом наборе (14 запросов) дал 1.000 по всем метрикам у обоих поисковиков и во всех
представлениях: набор был насыщен и представления не различал, тело «больших» модулей не достигало `max_chars`.
Поэтому набор усилен; числа ниже получены после усиления.

e5, free и mixed, все запросы (n=23):

| Представление | hit@1 | recall@5 | mrr@10 | ndcg@10 |
|---|---|---|---|---|
| Целый модуль | 0.696 | 0.870 | 0.767 | 0.822 |
| Фрагменты, max | 0.739 | 0.957 | 0.811 | 0.856 |
| Карточка + фрагменты | 0.783 | 0.913 | 0.828 | 0.868 |

recall@5 по тегам, e5:

| Срез | n | Целый модуль | Фрагменты | Разница |
|---|---|---|---|---|
| tail | 3 | 0.667 | 1.000 | +0.333 |
| large | 7 | 0.857 | 1.000 | +0.143 |
| distractor | 2 | 0.500 | 1.000 | +0.500 |
| paraphrase | 4 | 0.750 | 0.750 | 0.000 |
| base | 14 | 1.000 | 1.000 | 0.000 |

Лексический baseline: recall@5 0.913 у целого и у фрагментов, 0.913 у карточки с фрагментами; на paraphrase 0.750.
Пороги recall@5 ≥ 0.80 и mrr@10 ≥ 0.60 выполнены во всех представлениях у обоих поисковиков.
Правило выбора фрагментов выполнено для e5 (все запросы: +0.087, большие тела: +0.143).

Сходство e5 не калибровано: top-1 на negative 0.828–0.868, на положительных 0.838–0.910, диапазоны перекрываются.

## Выбранное представление

Фрагменты по процедуре с агрегацией max по артефакту. Основание: правило протокола выполнено, лучший recall@5
в целом (0.957), на хвосте тела (1.000), на больших телах (1.000) и на дистракторах (1.000).

Исходная гипотеза «карточка плюс фрагменты» не подтверждена по recall@5 (0.913 против 0.957), но выше по hit@1,
mrr@10 и ndcg@10. Разница в пределах одного-двух запросов; карточка остаётся вариантом для проверки в #322/#324.

Ограничения вывода: срезы по тегам из 2–4 запросов; набор усилен после первого прогона; на paraphrase ни одно
представление не превышает hit@1 0.500, а лексический baseline по общим метрикам близок к e5. Выбор модели
эмбеддингов для #322 этим замером не обоснован.

## Отклонённые альтернативы

- Только целый модуль: хвост большого тела обрезается; на `tail` recall@5 0.667 против 1.000 у фрагментов.
- Окна фиксированной длины без границ процедур: рвут смысл процедуры (не измерялось).
- Эмбеддинг одного имени: не находит свободные запросы (не измерялось).
- Тело без заголовка: теряется вид и владелец (не измерялось).

## Решения для #322, #324, #329

- #322: форматы id артефакта и фрагмента; выбор модели эмбеддингов не решён.
- #324: границы фрагментов по процедуре и правило окон для тел без процедур.
- #329: протокол метрик и пороги выше; сходство не трактуется как вероятность, порога отказа нет.
