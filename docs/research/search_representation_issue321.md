# Поисковое представление форм и модулей и синтетический eval-набор (issue #321)

Исследование для эпика #320. Production-код, публичные API, CI и схемы не менялись.
Машиночитаемый набор: [`search_eval_issue321.json`](search_eval_issue321.json).

## Границы

Корпус и запросы синтетические. Результаты не описывают качество поиска на реальных
конфигурациях. Fake- и hash-эмбеддеры доказывают только механику, не релевантность.
Платные запуски и провайдерный SDK не использовались; реальный код никуда не передавался.

## Единицы поиска

| Единица | Идентичность | Источник |
|---|---|---|
| Модуль | `<owner_kind>:<metadata_type>:<owner_name>:<module_kind>` | `ModuleEntry` (#203) |
| Форма | `form:<object_type>/<object_name>/<container_name>/<form_name>` | 4-кортеж `FormRagIndex` |
| Фрагмент | `<id артефакта>#<процедура>`; без процедур — `<id>#L<начало>-<конец>` | предложение для #322/#324 |

В `ModuleEntry` нет синонима владельца. Синоним — требование к карточкам владельцев (#323), а не готовый вход.
Модуль с `read_status` `empty` и `whitespace_only` в индекс текста не входит, `missing` означает «файла нет».

## Текст документа

Заголовок `MODULE / kind / owner_kind / metadata_type / owner / синоним`, затем тело.
Слитные идентификаторы разбиваются по смене регистра (`РеализацияТоваров` → «Реализация Товаров»).
Точный поиск по имени и `form_name` выполняется вне эмбеддера, сравнением нормализованных строк.

## Эталон и классы запросов

Эталон — множество id артефактов (и фрагментов), не наличие слова. Классы: exact, free, ambiguous, negative, mixed.
В корпусе все 12 `module_kind`, формы, `object` внешней обработки и отчёта. Unresolved-виды (`Sequences`, `obj`
у `ChartOfAccounts`, `ChartOfCalculationTypes`, `AccountingRegister`) есть только в отрицательных запросах.

## Протокол метрик

Статус: согласовано владельцем в чате #321 (2026-10-06); в GitHub не записано.

- Exact: accuracy@1 = 1.0; ambiguous — полное множество кандидатов и статус неоднозначности; ложных exact на negative — 0.
- Semantic: hit@1, recall@5, mrr@10, ndcg@10 по артефактам; агрегация max по фрагментам, дубли удаляются.
- Пороги для free: recall@5 ≥ 0.80, mrr@10 ≥ 0.60.
- Фрагменты выбираются, если recall@5 не хуже целого модуля более чем на 0.05 и лучше на больших телах.
- Negative: только распределение сходства, порога отказа нет.

## Эмбеддер и воспроизведение

Вариант B: лексический baseline и локальная `multilingual-e5-small`. Ревизия модели, версии библиотек, `max_chars`
и команда запуска вписываются после прогона `measure`. Прогон выполняет владелец локально, без сети.

## Представление-кандидат

Двухуровневое: карточка модуля (заголовок и список процедур) плюс фрагменты по процедуре, агрегация max.
Это гипотеза до прогона. Числовое подтверждение выбора в этой версии отчёта отсутствует.

## Отклонённые альтернативы

- Только целый модуль: хвост большого тела обрезается.
- Окна фиксированной длины без границ процедур: рвут смысл процедуры.
- Эмбеддинг одного имени: не находит свободные запросы.
- Тело без заголовка: теряется вид и владелец.
