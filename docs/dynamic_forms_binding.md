# Связанные кандидаты динамической структуры

`v8unpack_agent.dynamic_forms_binding.bind_form_operations(text, relative_path,
*, declared_elements=(), declared_commands=(), declared_attributes=(),
max_chars=2_000_000)` — opt-in library API. Вход — один снимок модуля формы
и явно выбранные host типизированные описи имён. Файлы и модели не читаются,
`ElemIndex` не меняется. Ошибки анализа — `DynamicAnalysisError`, как у
[детектора](dynamic_forms_detector.md).

Возвращается frozen `DynamicBindingIndex`: `raw` — прямые операции до
связывания, `bound` — операции после локальных доказательств, `candidates` —
потенциальные эффекты, связи и диагностика. Исходные operation IDs сохраняются;
операции через доказанный alias коллекции и сложный receiver могут добавиться.
Идентичность источника, процедуры, offsets и условий проверяется. Модуль
не восстанавливает конечное дерево формы и не обещает выполнение операции.

## Доказательства и границы

Поддержаны локальное присваивание результата Add/Insert, копирование ссылки,
alias формы и коллекции, литеральные Find/индекс/имя, ссылки на ранее созданный
родительский элемент и команда с доказанным литеральным именем. Одинаковые
имена из разных процедур не объединяются. Параметры и переменные модуля
исключены из доказанного локального состояния: ByRef и общие переменные
требуют отдельного анализа. Произвольные функции не исполняются.

Ссылка на доказанное создание exact даже при partial-имени. Выражение условия
сохраняется точно, истинность unknown. Ссылка действует только в контексте
своей ветви. Вне ветви, после неизвестного присваивания, удаления или
непрозрачного вызова доказательство может стать unresolved. До анализа
фиксированной точки ссылки из внешнего контекста сбрасываются при входе в
цикл; новое создание внутри тела снова доказывает ссылку для этой итерации.
Число итераций и единственность экземпляра не выводятся. Execute/Goto приводят
к явному отказу всего модуля: они могут изменить и ранее посещённые позиции.

Для реквизитов поддержан закрытый локальный массив `New Array`, Add/Clear,
копии ссылок и `New FormAttribute(name, type)` ровно с двумя аргументами.
Установленное членство с уникальным литеральным именем корневого реквизита
даёт exact-ссылку на batch ChangeAttributes. Неизвестный массив, изменённое
описание, неоднозначное членство, вычисляемое имя, дополнительные квалификаторы
или вложенный путь остаются unresolved; произвольные операции над массивами
не интерпретируются. Отдельные удаления реквизитов не реконструируются.

Host передаёт только типизированные статические описи, полученные из
поддерживаемого источника. Неизвестные имена не считаются существующими.
Из свойств корневой формы без доказательства расширения поддержаны Title
и ReadOnly. Остальные совпадения с whitelist свойств элементов сохраняются
как unresolved с `unproven_form_property`. Совпавший статический реквизит
затеняет предполагаемый контекст формы.

## Кандидаты и связи

Схема JSON — `dynamic_form_bindings/1`. Кандидат содержит reference, procedure,
operation_ids, effect, resolution, conditional, condition_context_complete,
relations, diagnostics и evidence_sources. ID зависит от снимка, процедуры
и доказанного источника идентичности. Типы целей: form/element/command/attribute
и unknown. Declared-цель с effect=reference может не иметь собственных операций;
это не динамическое создание.

Эффекты: create/modify/delete/mixed/reference/unknown. Создание с последующими
присваиваниями остаётся create; создание с удалением — mixed. Все операции
остаются доступны. Связи parent/before/data_path/command/type указывают
source_operation_id, target, resolution и при наличии target_candidate_id.
Литеральный DataPath связывается только с доказанным корневым реквизитом;
вложенные пути и вычисляемые значения не достраиваются по догадке.

Статусы ссылки, имени, аргументов, отдельных операций и всей цепочки независимы.
Resolution цепочки — наименее точный из её составляющих и связанных кандидатов;
он не повышается до exact из-за точной ссылки. Например, создание с
вычисляемым именем partial, последующий setter литеральной ширины exact,
ссылка exact, общий кандидат partial. Доказанное членство массива не превращает
исходное выражение массива в exact-скаляр.

Диагностика сохраняет operation IDs: name_collision, multiple_values,
delete_then_use, repeated_delete, branch_scope, alias_invalidated,
cyclic_relation, attribute_membership_unknown, unsupported_construct.
Это потенциальные конфликты исходников, а не утверждения о конечном состоянии.
Последовательные разные значения не заменяются молча последним. Потенциальный
цикл parent делает цепочку unresolved. Никакие declared-элементы не дописываются
в дерево `ElemIndex`.

## Детерминизм и публикация

`to_dict()` / `to_json()` сортируют результаты и скрывают выражения по умолчанию;
`include_expressions=True` включает их для локального анализа. Имена, литералы,
пути и provenance остаются недоверенными данными. Сериализатор не обезличивает
результат; публиковать реальный JSON без отдельного обезличивания нельзя.

Ограничения детектора дополнены пределами очереди событий, локальных имён,
созданий, описаний реквизитов и сравнений конфликтов. Превышение даёт явный
технический отказ вместо молчаливого усечения. Публичные frozen записи
валидируют висячие ссылки, контексты процедур/ветвей/снимков и запрет повышения
статуса. Никакой вызов этого API не запускает модели, runner или CLI.

Измеримый межпроцедурный data flow — отдельное решение #216; передача в
FormContext и framed — #217. Общий контракт — [динамические операции](dynamic_forms.md).
